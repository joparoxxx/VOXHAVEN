# Guest-first AI setup (v0.6 development)

## Player experience
Basic office and native TXT/PNG tasks need no internet or account. Guest AI is the default. On the first chat or Connect as guest, the app automatically requests a Firebase anonymous account; on future sessions it refreshes that identity. No registration or manual model/API key entry. Personal OpenAI key remains optional in AI settings. Cloud chat needs internet. Chat history and game data remain local; Google/email linking and Firestore cloud saves are not implemented in this increment.

## Owner setup (not deployed)
1. Create a Firebase project at https://console.firebase.google.com/ and enable Authentication > Sign-in method > Anonymous. Obtain the project ID and web API key from project settings (Firebase web API key is an identifier, not the OpenAI secret). Restrict Firebase API quotas. 
2. Create a Cloudflare Workers account at https://dash.cloudflare.com/. In backend/wrangler.toml set FIREBASE_PROJECT_ID, FIREBASE_WEB_API_KEY, OPENAI_MODEL to a supported chat model available on your own account. Keep AI_ENABLED=false until checks pass. Initial guest quotas are 10 chat attempts per UID, 30 per IP and 100 total per UTC day. A failed upstream request counts; 512 maximum completion tokens per request. All quotas can be lowered. These limits are not a dollar guarantee.
3. From backend/, use a supported Node.js environment, authenticate with npx wrangler login, deploy with npx wrangler deploy, then run npx wrangler secret put OPENAI_API_KEY and enter a NEW rotated project key at the interactive prompt. Never commit or embed it. Set OpenAI project billing alerts and review usage. Workers secrets, not GitHub Secrets, are the runtime configuration. Do not turn AI on until authentication and concurrent quota tests pass.
4. Set AI_ENABLED=true in wrangler.toml and redeploy only after verification. Put the resulting HTTPS base URL (no trailing slash) in game/core/guest_ai.gd BASE_URL. This public URL is not a secret. Rebuild APK only when authorized. Never ship a key in the APK.
5. Test: unsigned/wrong-project/expired tokens denied; valid anonymous guest can chat; concurrent calls cannot exceed global cap; 429 shows friendly limit; failed network leaves local gameplay usable; restart refreshes the same guest; no credentials in logs or APK. Run node --test backend/tests/policy.test.mjs locally or later CI. Real Firebase, Durable Object concurrency and live API integration remain unverified.

## Security and limitations
Firebase ID token RS256 signature verified using Google's securetoken public JWK endpoint, issuer/audience/expiry/issued-at/auth-time/subject/provider checked. Guest signup and refresh are throttled, and chat quota reservation is atomic in a single Durable Object (SQLite). No prompt logging in app code; provider retention policies and infrastructure logs still apply. Server model and output cap cannot be overridden by clients. AI is disabled by default; quotas fail closed on invalid configuration. Anonymous accounts can be created by attackers, IP rotation can bypass IP limits; global hard request cap remains. Add Firebase App Check / Play Integrity, abuse protection, revocation checks, privacy policy, account deletion and secure token storage before public launch. Refresh token is prototype app-private JSON, not Android Keystore encrypted. Uninstall may lose guest access. No public deployment yet. Firestore deferred because quota counters require atomic gateway enforcement and no cloud saves are implemented.
